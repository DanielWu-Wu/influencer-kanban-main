# 红人推广 / Influencer Ops 工作台

这是一个面向跨境电商海外红人推广专员的日常运营工作台。项目目标是把 YouTube 红人发现、飞书多维表格建档、Gmail/腾讯企业邮箱、AI 辅助翻译/回复、产品资料、合作状态跟进集中到一个清晰可控的桌面 Web 应用里。

当前主要工作面包括 **红人开发台、双邮箱邮件、合作项目、每日待办与工作日历、账号管理**：
从 YouTube 频道录入红人，查重并写入飞书双表，生成开发信和 Follow Up 草稿；
同时跟踪合作履约、物流/折扣告知、Gmail/腾讯来信及手动任务，并为团队成员提供账号隔离。

当前唯一现役交接入口是 [`docs/HANDOFF.md`](docs/HANDOFF.md)。根目录
`HANDOFF.md`、`PROJECT_HANDOFF.md`、`TODO.md` 和 `docs/AI_HANDOFF.md`
只保留旧链接兼容，不作为当前状态或优先级依据。

## 技术栈

- Framework: Next.js 16 App Router
- Frontend: React 19, TypeScript 5
- Styling/UI: Tailwind CSS 4, shadcn/ui, Radix UI, lucide-react
- Drag/drop: `@dnd-kit`
- Backend/API: Next.js Route Handlers under `src/app/api/**`
- Auth/storage: Supabase Auth，按账号隔离的资料、业务数据、云端设置和私密配置
- External integrations: Gmail API, Tencent Exmail IMAP/SMTP, Feishu Open Platform/Base API, YouTube Data API, OpenAI-compatible AI API
- Package manager: pnpm 9+

## 环境与集成配置

AI 模型走 OpenAI-compatible 接口。项目不内置 DeepSeek，用户可在设置或环境变量中配置自己的模型服务：

```bash
AI_API_KEY=
AI_API_URL=https://api.deepseek.com/chat/completions
AI_MODEL=deepseek-chat
```

Gmail OAuth 需要在 Google Cloud Console 启用 Gmail API，配置 OAuth consent screen，并创建 Web application OAuth Client。

生产环境常见变量：

```bash
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
GOOGLE_REDIRECT_URI=https://你的-vercel-域名/api/auth/callback
```

飞书、YouTube、Gmail、腾讯企业邮箱、AI 模型等连接信息主要通过设置页保存。AI“测试连接”使用独立的最小模型请求验证当前接口地址、API Key 和模型名称，不读取或伪造 Gmail/腾讯邮件会话；正式邮件起草继续要求真实邮箱账号和会话校验。飞书写入必须依赖用户保存的字段映射。

团队账号管理还需要先执行 `supabase/migrations/20260806_account_management.sql` 和
`supabase/migrations/20260807_account_admin_permissions.sql`，并在服务端配置：

```bash
SUPABASE_SECRET_KEY=
APP_ADMIN_USER_ID=
APP_SECRET_ENCRYPTION_KEY=
```

`SUPABASE_SECRET_KEY` 只能保存在服务端环境变量中，不能写入 Git 或返回浏览器；
`APP_ADMIN_USER_ID` 是 Supabase Authentication 中唯一主管理员的用户 ID；
`APP_SECRET_ENCRYPTION_KEY` 用于在服务端加密每位成员保存的飞书企业应用 App Secret，
必须作为敏感变量长期稳定保存，不能暴露给浏览器或在部署间随意更换。

腾讯邮件附件还依赖 Supabase 私有桶 `mail-attachments-temp`。桶必须保持非公开、单文件上限 25MB，
对象路径第一段使用当前 `auth.uid()`，并应用 `supabase/migrations/20260820_private_mail_attachments.sql`
中的上传、读取和删除 RLS；浏览器和发信 API 都不能绕过当前用户归属检查。

## 当前功能模块

- **红人开发台**
  - 4 个流程 Tab：红人录入、邀约确认、开发信、开发信跟进。
  - 支持批量输入 YouTube 链接、`@handle`、`channel/UC...` 等。
  - YouTube 识别会抓取频道基础资料、头像、国家/语言、公开邮箱、最近长视频。
  - 识别后自动进行飞书双表查重。
  - 可在录入列表直接补充邮箱，并写入资源库和开发记录表。
  - 资源库疑似收录时，hover 可查看飞书资源库疑似记录信息。
  - “确认为新红人”用于人工确认疑似记录不是同一个红人。
  - 新建开发记录时，可兜底把当前邮箱补写/追加到资源库邮箱字段。
  - 邮箱候选会合并 YouTube 公开简介、飞书资源库和开发历史记录；不同来源或多邮箱时由用户选择，人工修改后系统不再自动覆盖。
  - 欧洲国家代码写入中文国家名，频道语言结合文本特征和国家兜底判断。
  - 飞书富文本邮箱统一提取为有效地址，并在服务端阻止 `[object Object]` 异常文本写入。
- **邀约确认**
  - 选择目标产品、合作形式、合作想法、优先级、开发信语言。
  - AI 可根据频道名/简介识别联系人姓名和开发信语言。
  - 缺少目标产品、合作形式、合作想法、开发信语言时，不能进入生成开发信。
- **开发信**
  - AI 基于联系人姓名、频道简介、最近长视频、产品资料、合作形式、合作想法生成开发信。
  - 支持 3 个备选标题及中文翻译。
  - 支持单独重新生成标题或正文。
  - 生成后标题、外文正文和中文对照默认可直接修改，不再需要先点击“编辑邮件”；只修改标题或外文可直接保存草稿，修改中文后必须先点击“根据中文更新外文”。
  - 保存草稿时支持产品型号链接、产品主图和签名链接，产品主图位置仍可人工调整。
  - 保存到用户确认的 Gmail/腾讯邮箱草稿后，会按当前运营规则把线索移出开发信队列，并同步飞书双表状态；用户随后到对应邮箱检查和发送。
  - 开发信流程只保存草稿，不自动发送。
- **开发信跟进**
  - 可查看最近 7、10、14、30 天的飞书开发记录。
  - 固定规则是第 3 天二次跟进、第 7 天三次跟进；没有第 14 天跟进。
  - 可按红人绑定邮箱检查 Gmail/腾讯回复，区分人工回复、自动回复、退信和未找到初次开发信。
  - 点击单条或批量生成时只在当前浏览器标签页后台生成待审核内容，不立即创建真实邮箱草稿。
  - 审核窗口上方显示目标语言正文，下方中文可编辑；中文修改后必须重新翻译才能保存。
  - 批量审核使用宽屏双栏窗口，左侧选择待审邮件，右侧完整查看外文、中文和保存操作。
  - 已收到对方真实回信时，以黄色提示“已收到对方回信，无需跟进开发信”，并继续阻止后续开发信生成；退信和检查失败仍使用错误提示。
  - 用户明确点击保存到对应邮箱草稿后，系统按当前运营约定写回 Follow Up 状态和当天日期；不会自动发送邮件。
- **Gmail 与腾讯企业邮箱**
  - 使用统一邮箱账号模型和左侧邮箱切换；账号、草稿、AI 任务、翻译缓存、联系人历史和结果按 provider 与邮箱账号隔离。
  - 两种邮箱共用沙箱邮件阅读区：保留原始图片、字体和表格，邮件样式不能影响导航、邮件列表或回复工具栏；超宽、超长内容在正文内部滚动。
  - 共享富文本编辑器在加载旧草稿、转发、粘贴和拖入 HTML 前清理危险样式；可能提示部分格式被简化，仅打开草稿不会自动保存。验证范围与已知限制见交接文档。
  - AI 辅助回复区域保持固定栏宽，长中文、长链接和分析内容自动换行；邮件正文和空白处恢复普通箭头/文字选择光标，仅可点击位置显示手形。
  - AI 辅助回复与 AI 模板起草统一支持 39 种语言，新增日语；日语来信可以自动识别并选择日语回复，无法可靠识别时要求人工确认。
  - Gmail 收件箱成功刷新后的 60 秒内，切回窗口或恢复可见会复用同账号、同邮箱、同视图和同页结果，避免重复读取整页；到期自动刷新和手动刷新保持可用。更完整的配额边界见交接文档。
  - Gmail 保持原生线程和分类；腾讯提供收件箱、未读、星标、已发送、草稿、搜索、分页和刷新，不模拟 Gmail 的主要/推广/社交分类。
  - 两种邮箱均支持写信、回复、转发、翻译、AI 辅助、AI 模板、签名、附件和草稿；腾讯直接发送必须经过人工确认和倒计时，系统不会自动发送。
  - 腾讯会话只依据标准邮件关系头合并，不凭相同主题或联系人猜测；候选关系阶段不下载附件，确认会话后才读取正文，并使用 60 秒账号隔离缓存。
  - 编辑已有 Gmail/腾讯草稿会保留多收件人、抄送、密送、普通附件、内嵌图片和已有签名；原始内容加载不完整时禁止覆盖。
  - 查看带 `SENT` 标签的已发送邮件时，默认阻止邮件正文中的第三方远程图片、背景和样式资源，避免看板触发 Mailsuite/Mailtrack 打开记录；内嵌产品主图、附件、文字和普通链接不受影响。用户可只对当前邮件临时显示远程图片，但该操作可能触发追踪。
  - 翻译默认优先当前邮件正文，避免无谓翻译引用历史。
  - 双邮箱收件箱/未读首屏成功刷新发现新的未读来信时，先匹配红人再预翻译；首次快照只建立基线，不处理旧积压，不是即时邮件推送。
  - 每日待办刷新并匹配红人后，会把 Gmail 和腾讯近 72 小时内、最新来信后尚未回复且正文有效的来信加入预翻译；包括已完成待办，不受已读状态影响，继续排除自动回复和退信。后台按新到旧最多并发 2 封，前台另有 1 个优先槽，相同邮件和原文共用请求。
  - “中文已备好”只表示同账号、同邮箱、同邮件、同完整原文已有有效中文缓存，不是中文摘要或队列完成的推测。从待办打开默认中文；从普通邮箱打开默认原文，点击翻译直接使用已有中文。失败保留原文和重试入口，自动重试有上限。
  - 待办与详情共用正文解析及格式规范化，避免换行或截断差异造成重复翻译；新邮件或真实正文变化会重新翻译。缓存校验完整原文，优先翻译当前来信，引用历史继续使用独立入口。
  - Gmail 红人头像支持浏览器本地缓存和当前列表页预取。
  - 来信语言标签优先采用可信识别；置信不足显示待确认，AI 分析/翻译的实际识别结果按具体邮件与原文复用。用户手选的回复语言不被覆盖。
  - AI 辅助回复和 AI 模板起草只读取当前打开的真实会话：Gmail 按原生线程隔离，腾讯按标准邮件关系头隔离；服务端会拒绝混入其他线程或邮箱账号的上下文。
  - AI 回复正文支持流式显示，随后补充中文对照；模型不支持流式时自动回退兼容模式。
  - 顶部邮件生成进度为每项任务独立显示阶段百分比和进度条；排队为 0%，成功为绿色 100%，失败或中断保留最后真实阶段，重试回到 0%。
  - AI 辅助回复和 AI 模板起草的结果按账号、邮箱、线程、回复依据和回复方式隔离并保留 24 小时；重新打开同一邮件和同一回复方式时会恢复最近一次正文、中文对照、回复想法、语言、语气和模板，从生成进度打开时按任务编号精确恢复。新来信改变回复依据后不会自动套用旧正文。
  - 中文对照会校验简体中文比例并阻止英文原文冒充译文；正文和中文对照均支持流式显示。
  - 红人画像分析完成后不会自动覆盖当前草稿；用户可显式生成画像优化版、对比原稿并人工采用。
  - AI 辅助回复和模板起草生成一致的中外文后，可保存邮箱草稿或确认直接发送；只修改外文同样可用。中文/目标语言变化先更新外文；中外文都修改时可明确确认采用当前外文，后续内容变化使旧确认失效。
  - AI 辅助回复在停止输入约 1.5 秒后自动保存到项目云端，同一账号、邮箱、来信和收件人下再次打开时自动恢复；本机暂存保护未同步的文字。无需“保存/恢复系统草稿”按钮，不写入邮箱、不算邮件已处理。大附件不阻止文字保存，但未保留的附件会明确提示重新添加；发送成功保留发送标记，不再自动恢复成待发送内容。模板模式仍沿用生成记录恢复，没有新增自动系统草稿。已有邮箱草稿后直接发送不会自动删除原草稿，需避免两处重复发送。
  - 可选择线程中的任意真实邮件作为回复锚点，查看 From/To/Cc 参与者并确认最终收件人；无飞书红人匹配也不影响 AI 起草。
  - 从待办打开时，可先展示本轮已读取的单封来信与中文预览，历史和附件继续加载；预览不写入完整会话缓存，完整会话加载前禁用回复/转发。没有有效预览或译文时仍可能等待读取或翻译；“中文已备好”不表示历史和附件也加载完成。
  - 搜索框直接调用 Gmail 全局搜索，可查询较早邮件，不再只筛选当前加载页。
  - Gmail 与腾讯企业邮箱统一校验邮件日期并按真实时间排序；异常日期不会再制造未来时间或打乱最新邮件顺序。
  - AI 回复模板支持物流、折扣、合作模式、联盟邀请等内置模板，也可创建当前账号独立的个人模板。
  - 邮件签名可设置为“仅开发信”“仅正常邮件”或“两者都生效”。
- **每日待办与工作日历**
  - 手动任务支持截止日期/时间、编辑、删除、完成和撤销完成；待完成、今日已完成、历史已完成三组均可折叠。自动来信待办沿用 72 小时窗口，未完成也可能移出；手动任务不新增自动过期。这是用户确认保留的规则。
  - 并行读取当前可用 Gmail 和所有已连接腾讯邮箱的近 72 小时来信；每个来源独立显示实时、缓存、失败或断开状态，一个账号失败不清空其他账号。
  - 腾讯只依据标准回复关系头判断是否已回复；相同主题的无关邮件不会误判。常规邮件只读取正文分段，复杂 MIME 会回退完整原始邮件解析，可能包含附件字节，但不主动下载独立附件或生成附件预览。AI 摘要失败不影响任务展示。
  - 任务键、完成状态和摘要缓存按 provider、邮箱账号和真实邮件定位隔离；新外部来信晚于完成时间时会重新进入待完成。
  - 来信识别挂在全局工作台，不需要先进入每日待办。登录和账号配置就绪后，在网页可见时按新鲜度检查，定时周期为 5 分钟；恢复可见时补查，恢复联网或点击“刷新来信”可强制刷新。关闭网页后不会继续识别或翻译，不是邮件服务器即时推送。
  - 缓存待办先展示，取得有效正文后再预翻译；不能只凭中文摘要判断全文翻译已完成。任务行只显示邮箱类型，顶部读取状态保留账号。右箭头只切换到原账号并打开原邮件，腾讯按文件夹/UID 与 RFC Message-ID 定位，不修改飞书数据。
  - Gmail 和腾讯邮件正文成功显示后会标记当前真实会话为已读；选中邮件保留左侧蓝线，未读仍为淡蓝底、粗体和未读标记，已读为白底。
  - 日期使用本地日历语义，避免 UTC 时区转换造成日期偏移。
  - 工作日历同时汇总手动日程、未完成待办和飞书合作项目的确认合作、发货、到货、拍摄完成、预计上线、实际上线六类节点。
  - 点击日期打开当天详情，不会新建日程；项目提醒可在这里完成或恢复并同步每日待办。“新增日程”位于“刷新项目”左侧，合作节点显示频道头像。
  - 合作节点为只读，支持按需加载、60 秒缓存和手动刷新；点击节点可前往对应合作项目详情，逾期且未发布的预计上线节点显示为红色。
- **合作项目**
  - 提供列表、看板、日历、阶段多选、风险提示和项目详情。
  - 列表“下一步”列可添加项目提醒；提醒进入每日待办与工作日历，可打开原项目或已确认绑定的邮件线程。
  - 可后台写回物流/折扣告知状态以及发货、到货、拍摄完成、实际上线日期，并显示成功/失败提醒。
  - 物流、折扣和合作回复邮件支持 Gmail/腾讯邮箱；项目首次使用时人工确认具体会话或新邮件，项目绑定优先于红人绑定。
  - 同一页面内重复保存会更新原草稿；保存成功后按字段映射同步飞书“已告知”，不会自动发送邮件。
- **产品资料**
  - 设置页产品数据库已简化为产品资料卡。
  - 核心字段：产品名称、型号、产品页面链接、产品描述/卖点、主图、状态。
  - 高级资料默认折叠。
  - 主图保存在现有资源字段中，不新增 Supabase Storage。
- **飞书设置**
  - 支持红人资源库、红人开发记录表和详细合作记录表三套配置。
  - 每位成员可保存自己企业自建应用的 App ID/App Secret 并独立 OAuth 授权；App Secret 由服务端按账号加密保存，管理员和其他成员不可读取。
  - 设置页提供回调地址、应用创建步骤、只读检查、自动字段映射和样例记录预览。
  - 写飞书时必须使用字段映射，不硬编码字段名。
  - 支持读取飞书字段选项，用于内容类型等字段。
- **AI 助手**
  - 右下角圆形悬浮球，可拖动，靠近边缘自动半隐藏。
  - AI 用于辅助判断、翻译、生成邮件、提取信息；关键外部写入仍由用户确认或明确动作触发。
- **账号管理与数据隔离**
  - 使用固定主管理员账号创建成员账号，不发送注册或邀请邮件。
  - 主管理员可填写或修改姓名备注、停用、恢复账号及设置临时密码，但不能查看成员密码、业务数据、Gmail、飞书授权或密钥。
  - 新成员和被重置密码的成员首次登录必须修改临时密码，完成后才能进入工作台。
  - 产品、设置、待办、日历、红人、Gmail、飞书、AI Key 及缓存按账号隔离；切换账号时不会复用其他账号的数据或授权。
  - 临时网络或账号服务故障不会再被误判为账号停用；已确认的当前工作台会保留，并提供重试提示。
  - AI 起草、分析和翻译统一等待静默会话恢复；不显示“正在恢复连接”，恢复失败或 15 秒超时才提示。仅服务端明确确认 AI 尚未执行的登录失效允许自动重试一次；权限拒绝、服务异常、网络中断及已接收的流式请求不会自动再生成。双邮箱 AI 辅助回复与模板起草均适用。

## 后续开发注意事项

- 不要自动发送 Gmail 或腾讯邮件。腾讯直接发送只允许用户检查内容并明确确认后执行。
- 首封开发信、Follow Up、物流和折扣邮件沿用当前运营约定：用户确认并成功保存到所选邮箱草稿后，按既有字段映射写回“已发/已告知”；保存失败不得写回。
- 不要硬编码飞书字段名。所有飞书写入必须使用设置里保存的字段映射。
- 不要修改 Supabase 表结构或新增飞书字段，除非用户明确确认。
- 不要把 `SUPABASE_SECRET_KEY` 暴露给浏览器；管理员接口必须同时验证登录状态和 `APP_ADMIN_USER_ID`。
- 不要删除或随意更换 `APP_SECRET_ENCRYPTION_KEY`；更换后既有成员保存的飞书 App Secret 将无法解密，需要逐人重新配置。
- 管理员只有账号元数据管理权，不能绕过成员业务数据的 RLS 隔离。
- 不要把 YouTube API 当作邮箱来源。它只能读取公开频道资料，邮箱只能从公开简介文本中提取。
- 不要把 DeepSeek 描述为项目内置服务；项目只适配 OpenAI-compatible API。
- UI 要保持桌面运营工作台的信息密度，清爽、现代、可扫描，不做营销落地页风格。
