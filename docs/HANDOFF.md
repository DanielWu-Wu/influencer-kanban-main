## 1. 项目定位与核心入口

这是面向跨境电商海外红人推广专员的桌面 CRM 工作台，覆盖：YouTube 红人发现、
飞书双表建档、Gmail/腾讯企业邮箱、开发信与 Follow Up、AI 翻译/起草、每日待办、工作日历、
合作履约跟进和邮件告知。AI 负责辅助判断和生成，真实外部动作由用户确认。

### 账号管理与完全隔离

- 使用 Supabase Auth 登录，唯一主管理员由服务端 `APP_ADMIN_USER_ID` 指定；管理员不能在页面转让或新增管理员。
- 管理员可手动创建账号、填写或修改姓名备注、停用、恢复和重置临时密码；不发送邀请邮件，也不提供永久删除。
- 新账号及被重置密码的账号必须先修改临时密码；未完成改密或已停用账号不能访问业务数据。
- `account_profiles` 保存账号元数据，`user_data` 以 `user_id + data_key` 保存账号业务数据；设置、产品、红人开发及用户密钥均由 RLS 限制为当前正常账号。
- 管理员页面只读取账号元数据，不能读取成员密码、业务数据、Gmail 内容、飞书授权或密钥。
- Gmail、飞书、AI/YouTube 密钥与缓存均绑定当前账号；同一浏览器切换账号不会复用其他账号的资料或授权。
- 已移除固定每 30 分钟检查账号状态的轮询；继续使用 Supabase `persistSession` 和 `autoRefreshToken`，页面重新获得焦点或恢复可见时读取最新会话。
- 账号状态检查已区分明确停用/未开通/会话失效和临时网络或服务异常。只有明确会话失效时才刷新令牌并重试一次；临时异常保留同一账号已加载的工作台，不再自动当作账号停用退出。该机制降低误退出风险，但不等于永久登录。
- 账号管理依赖 `20260806_account_management.sql`、`20260807_account_admin_permissions.sql`、`SUPABASE_SECRET_KEY` 和 `APP_ADMIN_USER_ID`；Secret Key 仅允许服务端使用。
- 每位成员可配置自己企业的飞书自建应用。App Secret 使用服务端 `APP_SECRET_ENCRYPTION_KEY` 加密后保存在当前账号私密空间；管理员和其他成员不能读取。

## 2. 当前已实现能力

### 红人录入与飞书建档

- 支持批量识别 YouTube 频道、头像、近期长视频、公开邮箱、国家和推荐开发信语言。
- 飞书资源库/开发记录双表查重使用 60 秒快照和一次性索引；精确键冲突会阻止静默写入。
- “加入资源库”“新建开发记录”“快速建档”均先展示确认预览，确认后弹窗立即关闭，后台批量写入。
- 写入前按当前红人重新校验，其他红人的正常写入不再触发错误的“飞书数据已变化”提醒。
- 欧洲国家代码写入中文国家名；乌克兰等西里尔文本不会再因 `.com` 邮箱误判为葡萄牙语。
- 新建资源、开发记录和邮箱补写统一提取有效邮箱；飞书富文本对象不会再写成 `[object Object]`。
  服务端还会拦截任何包含该异常标记的待写字段。
- 邮箱候选会合并 YouTube 公开简介、资源库和开发历史记录，忽略大小写去重；来源冲突或多邮箱要求人工选择，手动填写/清空/选择后自动锁定，后续识别不会覆盖。
- 飞书写入必须使用用户保存的字段映射；不得硬编码字段名或自动修改表结构。

### 开发信、Follow Up 与邮件工作台

- Gmail 登录状态改为由应用级 Provider 统一维护，页面切换时不再由多个组件各自重复判断登录状态；短暂网络或会话检查失败不会把已确认连接误显示成“未登录”。
- Gmail 收件箱列表新增浏览器标签页内存缓存，按系统账号、Gmail 邮箱、邮箱视图/搜索条件和页码隔离；60 秒内返回 Gmail 页面时优先显示已有邮件并在后台同步，不先清空画面。
- Gmail 断开连接、切换系统账号或 Gmail 邮箱变化时会清理对应邮件列表与详情缓存，避免不同账号之间复用邮件内容；后台刷新失败时保留当前邮件并提供重试提示。
- 顶部“邮件生成进度”入口统一展示 Gmail/腾讯 AI 辅助回复、AI 模板回复、开发信、合作邮件和翻译任务；并发数可在 2 至 10 之间调节，超出并发限制的任务自动排队，完成后以现有弱提醒提供“打开”入口。
- 每项邮件任务独立显示真实业务阶段百分比：排队 0%、准备 10%、读取上下文 15%、生成正文 35%、整理结果 70%、翻译/分析 85%、成功 100%。运行中为蓝色，成功为绿色，失败为红色，中断为黄色；失败或中断保留最后进度，重试回到 0%，进度不会倒退。
- 邮件生成任务状态、必要的非敏感重试输入和已完成结果使用当前账号 `user_data` 中的 `email_generation_tasks` 保存，沿用既有 RLS；任务按系统账号、Gmail 邮箱、线程或红人隔离，默认保留 24 小时。
- 页面刷新或重新登录后可恢复已完成、失败和中断任务；上次仍为 `queued` 或 `running` 的任务会转为 `interrupted`，不会自动再次消耗 AI，只有用户点击“重试”才重新执行。
- 当前阶段的 AI 请求仍由浏览器执行，因此关闭页面、刷新或标签页被系统回收时，生成中的请求可能中断；尚未实现“网页关闭后服务端继续生成”的后台队列。
- 恢复任务结果时不会覆盖用户已经手动修改的编辑器内容；云端快照禁止保存 Gmail Token、AI API Key 和无关完整邮件历史。云端同步失败时保留当前内存内容并明确提示，不假装已经保存成功。
- 首封开发信可按中文对照修改后重新翻译为目标语言；保存到所选 Gmail/腾讯草稿前仍需人工检查。
- 首封开发信生成后，标题、外文正文和中文对照默认可直接编辑，不再显示“编辑邮件”或“编辑正文”开关。只修改标题或外文可直接保存；修改中文后必须先根据中文更新外文，成功后才恢复保存草稿。
- 当前运营约定：首封开发信草稿保存成功后，用户立即前往对应邮箱检查和发送；系统不得自动发送。
- 一次/二次 Follow Up 按红人绑定邮箱读取真实 `SENT`、`DRAFT`、人工回复、自动回复和退信状态。
- 单条和批量按钮只在当前浏览器标签页后台生成目标语言正文与中文对照，不立即创建真实邮箱草稿或写飞书；结果按账号缓存 30 天，关闭/刷新标签页不保证任务继续。
- 审核窗口允许修改中文，必须点击“根据中文更新外文”后才能保存；批量结果逐封审核、逐封保存，不提供全部直接保存。
- 一次/二次 Follow Up 批量审核窗口已扩大到桌面宽屏布局，左侧待审邮件列表加宽，右侧外文、中文和操作区保持独立滚动；不改变生成、保存或写回逻辑。
- 已确认收到真人回信时显示黄色“已收到对方回信，无需跟进开发信”，并继续阻止后续开发信生成；退信、检查失败和缺少初次开发信仍保留异常语义。
- 用户明确点击“保存到所选邮箱草稿”前会再次检查回复、退信和重复跟进；草稿成功后按当前运营约定写回对应 Follow Up 状态和当天日期。邮箱草稿成功而飞书失败时只重试写回，不重复创建草稿。
- Gmail 与腾讯 AI 辅助回复、AI 模板起草只读取当前打开的真实会话：Gmail 按原生 `threadId`，腾讯按 `Message-ID` / `In-Reply-To` / `References` 严格关系隔离；服务端再次校验邮箱账号、目标邮件和上下文身份，发现混入其他线程时直接停止生成。
- AI 回复支持 SSE 流式正文；不支持流式时回退普通 AI 路由。快速切换腾讯邮件时只有最后一次会话请求可以更新页面，旧请求不能覆盖新邮件。
- Gmail 搜索直接使用 Gmail 全局查询，可搜索较早邮件；每日待办箭头可打开指定线程。
- Gmail 线程详情优先复用 5 分钟缓存并保持详情区展开，未命中缓存时使用加载状态后台读取，减少切换线程时的短暂空白和闪烁。
- 每封带 `SENT` 标签的已发送邮件在看板中默认阻止 `http/https` 远程图片、背景、样式和 SVG 资源，避免 Mailsuite/Mailtrack 追踪像素把运营人员查看误记为红人打开；同线程的普通来信不受影响。
- `cid:`、`data:image/...` 和 `blob:` 内嵌图片继续显示，因此开发信内嵌产品主图不受影响。只有实际拦截到远程资源时才显示提示；人工点击“显示远程图片（可能触发邮件追踪）”只放开当前邮件，刷新、切换线程或切换账号后恢复保护。
- 该保护不修改 Gmail 邮件原文、历史追踪记录或 Mailsuite 数据，只能阻止本看板默认查看产生的新远程资源请求；用户主动放行、邮件服务器扫描、其他客户端和收件人打开仍可能被追踪。
- 每封真实 Gmail 邮件都可被选择为回复上下文锚点，即使没有飞书红人匹配；线程展示 From/To/Cc 参与者，自发邮件有多个候选收件人时要求人工选择，未确认收件人仍可生成但不能保存草稿。
- AI 回复的中文对照要求完整简体中文，并做中文比例和英文复制校验；外文正文与中文对照均支持流式显示。中文可编辑，确认后重新翻译目标语言。
- Gmail 红人画像分析在后台完成后不会自动覆盖当前草稿；用户可显式点击“结合画像优化草稿”，对比原稿与优化稿并人工采用，用户已写入的预算、日期和合作条件优先保留。
- AI 同时生成外文和中文对照后可直接保存到当前邮箱草稿；点击“根据中文更新外文”后，中文和目标语言成为当前翻译依据，编辑器会在排队或翻译期间显示绿色“正在根据中文更新外文邮件”。
- 中文或目标语言随后变化时，必须重新翻译才能保存；外文可手动加入表情、调整措辞或排版，界面显示“外文已手动调整”，仍可直接保存草稿。
- 外文已人工润色后再次根据中文翻译会先提示可能覆盖当前外文；“直接发送”继续要求用户完成更严格的中文人工确认，不因放开草稿保存而扩大权限。
- AI 回复模板提供物流、折扣、常规合作和联盟邀请等内置规则，也支持当前账号独立的个人模板；模板管理使用编辑入口而非复制图标。
- AI 模板起草的“用自己的话补充事实”支持双模式输入：短内容可在紧凑文本框中直接输入，长内容可通过独立的“打开大编辑器”进入专注编辑；两处实时共享内容，大编辑器打开后聚焦到内容末尾，关闭不会丢失当前组件会话内的输入。
- AI 模板起草已收敛为“生成外文与中文对照 → 检查中文 → 必要时按中文更新外文 → 保存到当前邮箱草稿”；模板模式不再展示回复要点、缺失信息和风险审查区，普通“AI 辅助回复”分支不受影响。
- AI 回复模板管理弹窗使用自身可滚动内容区，标题和底部操作保持固定；在浏览器 100% 缩放且窗口高度不足时，可以滚动到“默认语气”并保存。
- Mailsuite/Mailtrack 等通知地址在联系人解析和 Gmail 草稿 API 两层拦截。
- Gmail 签名新增三选一范围：仅开发信、仅正常邮件、两者都生效；旧配置默认按两者都生效。
  AI 提示词明确禁止签名，程序还会按当前账号配置的签名内容移除 AI 末尾重复姓名/落款，再由统一渲染逻辑追加项目内签名。
- 合作项目的物流/折扣告知邮件支持中文对照编辑、重新润色翻译、后台生成，并使用用户确认的 Gmail/腾讯项目会话；
  只创建所选邮箱草稿，不自动发送；用户确认保存草稿成功后，自动勾选飞书中对应的“物流信息已告知”或“折扣信息已告知”。
  邮箱草稿成功而飞书同步失败时保留已创建的草稿，并提供仅重试飞书同步的入口，不重复创建草稿。
  发货日期在交给 AI 前统一转换为上海业务时区的 `YYYY-MM-DD`，不允许模型自行换算时间戳、时区或从物流编号推断日期。
  Gmail 选择回复锚点时排除表情回应和已有 `DRAFT`；腾讯使用严格标准关系头。当前页面内重复保存会更新原邮箱草稿；原草稿已被人工删除时，下一次用户确认保存才重新创建。

### 双邮箱与腾讯企业邮箱

- 已建立 Gmail / 腾讯企业邮箱通用账号模型，邮箱切换入口位于邮件页左侧栏；腾讯凭证只在服务端加密保存，API 每次按当前系统用户校验 `mailAccountId` 归属。
- 腾讯页面已覆盖写信、收件箱、未读、星标、已发送、草稿、搜索、分页、刷新、附件下载、邮件详情、回复、转发、AI 辅助回复、AI 模板回复、翻译、签名、草稿和人工确认发送。
- 腾讯发送通过 SMTP；发送前仍需用户确认，并保留延迟发送/倒计时取消。SMTP 请求真正提交后不能保证撤回。发送成功与“已发送”文件夹同步结果分开提示，避免同步失败诱导重复发送。
- 腾讯草稿更新采用“先保存新版本，再删除旧版本”；旧版本删除失败时保留成功结果并明确警告。Gmail 草稿 ID 与腾讯文件夹/UID 不共用。
- Gmail 与腾讯已有草稿均使用完整收件人、抄送、密送、富文本、普通附件和 `cid:` 内嵌图片编辑上下文。任一原始附件或内嵌图片加载失败时禁止覆盖原草稿；编辑已有草稿不会自动重复追加签名。
- Gmail 与腾讯邮件时间统一优先采用可验证的邮件头时间，并使用服务端内部时间等安全来源回退；异常或未来日期不会再制造错误时间，列表和会话按解析后的真实时间稳定排序。
- 腾讯会话只使用 `Message-ID`、`In-Reply-To` 和 `References` 建立关系，不再凭主题、联系人或时间接近模糊合并。缺失或损坏标准关系头时保持独立，避免同一红人的不同项目串线。
- 腾讯会话加载已改为：完整读取当前邮件 → 轻量读取候选关系头 → 只批量读取确认属于会话的正文。候选关系判断不下载附件；同请求去重、并发请求合并，并使用按系统用户和邮箱账号隔离的 60 秒短缓存。手动刷新绕过缓存，草稿/发送/标记变更后使缓存失效。
- 合作项目邮件优先使用项目邮箱绑定，其次使用红人邮箱绑定；没有有效绑定时要求人工选择。项目首次回复还必须选择具体会话或“新建独立邮件”，项目会话绑定不会覆盖红人全局绑定。
- 首封开发信、Follow Up、物流、折扣和合作回复已接入邮箱身份；草稿、AI 任务、翻译结果、联系人历史和顶部生成进度均带 provider 与 `mailAccountId`，避免 Gmail/腾讯或不同账号互相覆盖。
- 当前运营规则保持不变：首封、Follow Up、物流或折扣邮件在用户确认并成功保存到对应邮箱草稿后，即按既有飞书字段映射标记“已发/已告知”；草稿保存失败时不得更新飞书，飞书写回失败时不得重复创建草稿。
- Supabase 私有桶 `mail-attachments-temp` 已由用户在生产控制台创建为非公开、单文件 25MB，并执行按 `auth.uid()` 路径隔离的上传/读取/删除策略；对应迁移文件已包含在 `1.2.0` 提交中。附件下载已由用户在本地确认可用，大附件发送与双用户越权测试仍待真实验收。

### 每日待办与工作日历

- 手动任务支持标题、放大描述、优先级、默认当日截止日期、截止时间、编辑、删除、完成和恢复；高密度行布局可在一屏显示更多任务。

- 每日待办并行读取当前可用的 Gmail 授权账号和所有已连接腾讯企业邮箱；每个邮箱独立记录实时、缓存、失败或断开状态，一个邮箱失败不会清空其他邮箱的实时结果。

- 任务键和完成状态按 provider、`mailAccountId` 及真实线程/文件夹/UID 隔离；旧版无来源任务只在能够唯一匹配 Gmail 任务时迁移，不用主题或正文相似度跨账号合并。
