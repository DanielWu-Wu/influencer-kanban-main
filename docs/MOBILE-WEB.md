# 手机网页首版

2026-10-14 核对：当前 main / ba81fcf，源码更新提示为 1.4.0「手机网页与邮件体验优化」；本次排版修复仍为未提交的本地修改，未推送、部署。目标设备为 iPhone 14 Pro Max，主要按竖屏使用；手机布局在小于 768 CSS 像素，或宽度小于 1024、高度不超过 600 的触摸横屏视口启用，普通桌面继续使用现有界面。下方 2026-10-13 验证属于历史记录。

## 已实现范围

- 手机使用左上角菜单切换待办、邮件、合作及退出登录；按用户反馈移除底部导航，为内容区腾出空间。其他模块继续在电脑使用。
- 每日待办：触摸按钮、长标题换行、新建/编辑表单、完成/恢复与关联邮件/项目入口；沿用原状态与保留规则。
- Gmail/腾讯邮箱：窄屏列表、搜索、阅读、返回；回复区展开后占用阅读工作区，收起及切换回复方式保留已挂载编辑器的内容。
- 两类 AI 回复及手动回复：沿用原生成、翻译、附件、草稿和发送流程。手机点击直接发送先审核发送邮箱、收件人、主题、最终正文及附件名称；内容或对象变化使旧审核失效。确认后调用原发送及倒计时流程，取消/失败保留编辑内容。电脑端发送路径不变。
- 合作项目查询：卡片列表、搜索、阶段/风险筛选、更多产品/站点/日期筛选及全屏详情。手机详情只读显示日期和告知状态，不提供合作编辑、合作告知邮件或视频监测入口；电脑入口保留。
- 可见视口变化时适配键盘空间；正常页面缩放保留原生行为。弹窗可滚动，主要触摸控件至少 44 像素，输入框采用手机可读字号；不修改保存到邮件中的默认字体格式。

- 手机线程标题与参与者入口使用一行；红人频道及合作/回复状态默认保留，地区、平台、粉丝、邮箱和飞书操作收进「资料与操作」；完整收发信息可展开，飞书预览与人工确认仍可访问。桌面保持展开显示。
- 新邮件、转发和编辑邮箱草稿共用修正后的全可见视口弹窗。表单主体可滚动，发送/草稿按钮固定在可见底部；输入法打开后定位到正在编辑的字段，格式工具在竖屏中单行横向滚动，视觉字号不改变保存正文的默认字体。

- AI 助手在手机覆盖可见区域，四个页签内容独立滚动，长记录换行，输入和发送处于键盘上方。横屏键盘打开时优先显示编辑区，收起键盘后恢复页签。关闭重开保留本次输入；悬浮球在编辑或邮件弹窗/回复区域打开时隐藏，结束后恢复，并限制在手机可见高度内。

## 稳定性修复（2026-10-13）

- 同一系统账号、邮箱、会话及回复依据的发送任务在当前网页中共享状态。倒计时提示关闭后重开邮件，或切换手动/模板/AI 回复，不会新增重复任务；编辑器仍可在倒计时结束前取消。提交中不提供撤回承诺。发送成功后显示已发送；明确点击「撰写另一封回复」才重新进入编辑，旧生成/翻译记录不自动复用。
- 手动回复正文、模板补充事实和模板选择按系统账号及完整回复身份在浏览器本机暂存，编辑时立即写入，返回目录或刷新后恢复。旧生成记录不覆盖后来修改的事实/模板；暂存失败时保留当前网页内文字并显示限制。该暂存仅覆盖文字及模板选择，不自动创建真实邮箱草稿，也不新增附件跨刷新恢复或跨设备同步。
- 主界面的最小高度随手机可见高度收缩；弹窗定位同时处理可见高度和顶部偏移，待办弹窗操作区在滚动时保持可触达。保留原生页面缩放。
- 两类 AI 回复的已完成生成任务及时解除等待状态，迟到的运行中状态不再把已应用的结果重新锁成「正在生成」。

发送任务及防重结果仍在当前登录网页内存中，不是服务端持久发送队列。刷新、关闭网页、锁屏或切换应用的真实行为仍需 Safari 真机验收，不能承诺后台持续发送。发送报错时仍需核对已发送文件夹，不自动重试。

## 本地预览

项目现有开发端口为 5000。已有服务时直接访问，不重复启动；没有服务时在项目目录运行 `pnpm dev`，无需安装依赖或发布。

电脑 Chrome/Edge 打开 `http://127.0.0.1:5000` → F12 → Ctrl+Shift+M → 设置 430×932 → 点击左上角菜单切换待办、邮件、合作。切回桌面宽度检查原页面。

手机不能用 `localhost` 访问电脑。当前核实的服务只监听电脑的 127.0.0.1；直接用 iPhone 访问需后续安排同 Wi-Fi 的局域网预览及防火墙检查。不能据此宣称手机真机已经验收。

本地应用仍可能连接真实服务；布局预览不等于测试账号。真实发送、邮箱草稿、飞书写回和收费 AI 测试仍需用户明确授权。
