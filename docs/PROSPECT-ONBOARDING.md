# 红人建档与邀约

2026-10-09 按当前工作区源码复核。建档与邀约功能已本地实现；没有取得包含这些未提交改动的部署凭证。本次知识收尾没有执行真实飞书、邮箱或收费 AI 请求。

## 操作

1. 识别频道，确定一个收件邮箱。准确关联已有资源自动复用，只有疑似匹配、冲突或未确定邮箱需要处理。
2. 录入页可填写开发备注；目标产品、合作形式和写信语言只在“邀约确认”中选择，不前置。
3. 点击“建档并进入邀约”：新资源先做 AI 频道类型分类，手动设置优先；分类失败类型留空继续。创建本轮开发记录后进入邀约，附带邮箱同步失败不阻塞写信。
4. 在“邀约确认”中选择产品、合作形式和语言，核对后逐条确认生成；批量确认入口隐藏，红人列表不设筛选框，本轮时间及可选状态映射说明不展示。邮件仍需审阅后手动保存草稿，发送不自动执行。
5. 再次发起新轮次：红人录入 → 显示历史轮次 → 选择旧红人 → 建档并进入邀约。旧记录、邀约、邮件和草稿保持独立。旧任务的“重试未完成步骤”继续原轮次。

## 数据与兼容

- 使用已有线索 JSON 存储和已有云同步，不新增数据库表，不要求迁移。
- 每轮独立线索 ID/轮次 ID、发起时间、开发记录编号、任务日志、邀约信息、开发备注与邮件草稿；新轮次复用频道资料和已确认资源关联，不复用旧邮件、旧任务和合作承诺。
- 飞书只使用保存的字段映射。“开发流程状态”为选配，未映射时只保存本地阶段、不提交空字段更新，不阻塞进入邀约；邀约确认页不展示这项技术说明。录入页仍保留轮次时间，不能把“邀约页隐藏”理解为所有页面都移除轮次信息。
- 同频道多条开发记录是历史轮次；资源库多条匹配或不同频道共用邮箱仍需核实。
- “仅新建开发记录”和“继续本轮邀约”保留，兼容旧条目及部分完成任务。
- 保存邮箱草稿后写“已发”的旧规则本次未改变，其业务含义需单独确认。

## 性能与防重复

- 查询必要字段，同批共享索引与快照；已确认资源和阶段更新按记录编号核对。
- 写前刷新每表每批复用，不逐行下载整表；进行中的强制刷新共享请求。
- 同表同类按依赖波次批量提交，每组最多 20 条，提交前保存原始批次内容和标识。
- 成功步骤不重复创建；明确失败按本条原始单条标识和冻结字段重试，不重新提交同批其他记录；结果不确定先核实，刷新不自动写入。
- 本机日志保存失败阻止外部提交。沿用既有账号与映射隔离，不改变权限。
- AI 合作想法自动准备最多三条并行；手动信息不覆盖，同一输入失败不自动循环重试。
